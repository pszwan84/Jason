## 1. 核心判断

2026-09-14 起：Mock 社交商城已接到主页面。货架 18 条，热度榜可点赞评论改排序，交换可沉淀，好友从成交后产生。仍是单机演示。

仍缺：

- 「孵化室」是规则提炼，不是 LLM
- 「围炉」评论计热度，但不单独解锁贡献后开放（仍走交换卡）
- URL 全程 `/`
- 无真实多用户

所以下一步不该再铺新页面，而应该**把一条真实链路打通并做成可演示的瞬间**：
> 一个真实问题 → 一次真实提炼 → 一张真实交换卡 → 一次真实共创产出。

---

## 2. 推荐顺序

### P0-A｜真实提炼：让孵化室真的"长"出内容（PRD 模块一）
粘贴一段经历 / 一段知乎回答 → LLM 按 5 步范式产出草稿 → 一键填进孵化室。
- 这是**唯一能当场让人"哇"的瞬间**，也是把"17 次分析 / 26 个案例"这类假数字变成真的起点。
- 落点：孵化室加"从一段经历开始"入口；产出直接写入本轮的 `Kit` 模型（数据结构已就位，不用重构）。
- 成本：1 个 API 路由 + 1 段 prompt + 1 个表单。**风险最低、收益最高。**

### P0-B｜最小持久化：刷新不丢东西（PRD 模块四）
- 先用 `localStorage`（或 `.openai/hosting.json` 里已预留、当前为 `null` 的 D1 绑定）持久化：我培养的 Skill、收藏、交换卡、共创任务。
- 这是"产品感"的门槛线：现在的每一次刷新都会清空用户刚建立的一切。

### P0-C｜交换卡闭环 + 围炉解锁（PRD 模块三）
- 提交交换卡 → 落库 → 出现在「消息」→ 对方确认 → 解锁"贡献后开放"的完整内容。
- 只要这一条闭环成立，"开放阶梯"才从**文案**变成**机制**，PRD 里最有说服力的部分才站得住。

### P1-A｜深链与路由
- 全程 URL 是 `/`：不能分享、刷新回不到原页、后退键无效。
- 低成本方案：hash / search params（`?page=incubator&skill=2`）。**可分享是这个产品传播的前提。**

### P1-B｜把 63% 变成"看得见的算法"
- 现在弹窗只给一段文案。哪怕仍是示例数据，也把供需分解展示出来（PRD 里的 `α·(Sᵢ·Dⱼ)+β·(Sⱼ·Dᵢ)−γ·(Sᵢ·Sⱼ)`）。
- 否则评审追问"63% 怎么来的"会答不上。

### P1-C｜细节与性能
- 共创"回答并继续"要真的推进 AI 主持人的下一个问题（现在只 toast + 清空）。
- 刘看山 3 张 GIF 各 ~950KB，探索页首屏要拉 ~1.9MB → 换 WebM/APNG 或压到 <200KB。
- `public/garden.png` **2.2MB 且全项目零引用**（已确认），可直接删或确认用途。
- 顺手清零 lint：27 条错误集中在 `components/ui/*`（shadcn 上游代码）+ 3 处 `<label>` 未关联控件 + toast 用 `role="status"`（建议 `<output>`）。

### P2｜关系图谱与消息的真实性
- "我的关系"目前只有 6 条连线、无文字节点，"图谱"的信息量不足；消息三条都是预置数据。
- 这两块的"假"感最强，但**优先级最低**——它们依赖 P0-B/P0-C 的真实数据。

## 3. 明确先不做

- ❌ 不做多用户 / 账号体系（用双身份切换或 URL 参数模拟对方即可）
- ❌ 不做 3D 场景与多 Agent（表现层已足够，先补机制层）
- ❌ 不做完整插件化 manifest（PRD 方向 C 是加分项，不是本轮瓶颈）
- ❌ 不动视觉系统（现有调性已被认可，改版风险大于收益）

---

## 4. 需要决策的三件事

1. **真实链路做到哪一步？** 只有"提炼"用真模型，还是"提炼 + 匹配 + 交换确认"全部落库？
2. **后端用 D1 还是 localStorage？** 前者能演示"真实协作"，后者 1 小时内可完成。
3. **演示脚本定哪条？** 建议固定为：`知乎高赞回答 → 提炼成 Skill → 被林然用交换卡申请 → 共创产出复合 Skill`，所有 P0 工作都对齐这条脚本。
