## 1. 产品背景与第一性原理 (First Principles)

### 1.1 现实痛点
* **知乎生态的知识沉淀瓶颈**：知乎拥有中文互联网最优质的专业答主与高密度经验，但这些隐性经验（Tacit Knowledge）通常散落在长篇回答、专栏或个人脑海中，难以被他人直接复用，容易随时间沉没。
* **市面 Agent/Prompt 工具的死穴**：大部分“Prompt 市场”充斥着千篇一律的套话工具（如“一键写文案”），缺乏真实业务场景反例与边界条件；没有长效维护者，无法形成协作演进机制。
* **人际连接的弱动机**：单纯的“交友”或“私信请教”往往陷入信息不对称与白嫖困局，缺乏一个平等、具体、基于价值交换的连接支点。

### 1.2 核心解法：经验资产化 + 双边互补匹配
1. **经验资产化（Skillification）**：将答主的个人解题思维，提炼为具有 5 步范式（提取问题 → 寻找基线 → 剥离贡献 → 边界条件 → 验证反例）的标准化 Skill。
2. **知识互补匹配（Complementary Matching）**：不同于常规的“兴趣相似”推荐，本系统基于经济学双边匹配理论，寻找**能力结构互补**的人（如：经管学者提供业务现实案例 + 理工工程师提供量化统计模型）。
3. **微观交换机制（Mechanism Design）**：通过“交换卡”与“贡献后开放”设计，以“真实案例/反例”或“交叉测试”作为对价，消除白嫖，促成深度共创（Co-Lab）。

## 3. 系统架构与功能模块规划

系统分为四层递进架构：

```
[ 展示层 / UI ]  探索漫游 · 个人栖息地 · 孵化室 · 共创实验室 · 关系图谱 (刘看山吉祥物)
       ▲
[ 机制层 / Mechanism ] 开放阶梯权限 · 交换卡流转契约 · 围炉反例贡献 · Skill 族谱溯源
       ▲
[ 算法层 / Matching ]  双边知识互补度模型 (S_ij) · 跨界语义关联度 · 推荐理由生成
       ▲
[ 数据层 / Ingestion ] 知乎回答/专栏解析 · 5步范式LLM抽取器 · 本地持久化存储
```

### 3.1 P0 核心功能（黑客松交付基准 / MVP）

#### 模块一：知乎内容到 Skill 的标准化提炼引擎（Ingestion Pipeline）
* **输入**：用户输入知乎回答链接、文本或 Markdown。
* **处理（LLM 5步提炼链）**：
  1. 识别核心问题（Problem Definition）
  2. 提取基准现状（Baseline Approach）
  3. 提炼创新方法论（5步可执行步骤）
  4. 明确已知局限与边界条件（Boundary & Constraints）
  5. 沉淀初始案例与正反例（Case Grounding）
* **产出**：直接填充至「孵化室」草稿，支持一键发布。

#### 模块二：双边互补匹配引擎（The Matching Engine）
* **经管数学模型**：
  设用户 i 的能力供给向量为 S_i，需求向量为 D_i；用户 j 的供给向量为 S_j，需求向量为 D_j。
  互补度得分计算公式：
  互补得分 = α · (S_i · D_j) + β · (S_j · D_i) - γ · (S_i · S_j)
  （其中 α、β 为双向供求满足权重，γ 为同质化竞争惩罚项，确保推荐出的关系是“能力互补”而非“完全重合”）。
* **业务落地**：
  * 右侧栏「跨界漫游」动态生成科学的匹配百分比与 1 句话推荐依据。
  * 「为什么推荐给我」弹窗展示两人供给与需求的交织点。

#### 模块三：机制状态机与交换卡闭环（Exchange Mechanism）
* **开放阶梯**：
  * `完全开放`：直接查看与使用。
  * `交换后开放`：索取方必须提交一份「交换卡」（说明自身是谁、痛点背景、能带来的对价：真实案例/测试数据）。
  * `贡献后开放`：索取方必须在「围炉」讨论区提交经原作者审核通过的“1 个真实反例”或“1 次交叉测试”，方可解锁完整流程。
* **共创闭环（Co-Lab）**：
  * 两人交换成功后，自动生成「共创实验室」看板。
  * 任务清单状态流转（对齐标准 → 建立流程 → 交叉测试 → 发布复合版本）。
  * 生成「Skill Family Tree（技能族谱）」：记录母本 Skill 与衍生版本。

#### 模块四：全栈状态持久化与 API 体系
* 抽离当前写死在前端的 `page.tsx` 数据，提供标准 RESTful API：
  * `GET /api/skills`：列表与馆区筛选
  * `POST /api/skills/incubate`：提炼并创建 Skill
  * `POST /api/match/recommend`：计算并获取互补推荐
  * `POST /api/exchange/cards`：发送与审批交换卡

## 6. 社交商城 MVP（2026-09-14 确认）

路演改走 SkillHub **操作**（逛货架、看热度、交换、加好友），不是 SkillHub 下载站。

- Mock 货架：`skill-zoo/data/skills.json`（18）+ `people.json`（8）。换货只改 JSON。
- 热度 = 10×赞 + 6×评 + 15×成交交换。只买商城排序，不买货。
- 完全开放可直接收入沉淀；交换后开放 / 贡献后开放必须走交换卡。对方同意在本机模拟。
- 好友只能从成交交换后「加为同行」，没有通讯录。
- 仍无账号、无 API、无部署。模块一 LLM 抽取、模块四 REST 不在本轮。
